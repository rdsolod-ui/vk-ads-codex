# Кабинет и рекламная иерархия

DOC: [этапы создания](https://ads.vk.ru/help/general/start/creating), [редактирование](https://ads.vk.ru/help/general/start/edit_campaign), [статусы](https://ads.vk.ru/help/general/start/campaign_status), [AdPlan](https://ads.vk.ru/doc/api/object/AdPlan), [AdGroup](https://ads.vk.ru/doc/api/object/AdGroup), [Banner](https://ads.vk.ru/doc/api/object/Banner).

1. Сверьте имя кабинета и клиентский контекст; путь URL может содержать делегированный контекст. Зафиксируйте его только в приватной рабочей записи. Различайте агента, клиента, менеджера и партнёра монетизации.
2. Кампания задаёт цель и объект продвижения. Группа объединяет аудиторию, размещения, расписание и ставку/бюджет в зависимости от настройки оптимизации. Объявление содержит текст, медиа и ссылки. Изменение в родителе может затронуть несколько дочерних сущностей.
3. Цель и рекламируемый объект уже созданной кампании нельзя просто заменить по справке; сначала подтвердите текущее ограничение, затем планируйте новую кампанию при разрешении. Не удаляйте старую ради обхода ограничения.
4. Для API доступные тексты, URL-роли, content-роли и таргетинги зависят от package. Читайте [Packages](https://ads.vk.ru/doc/api/resource/Packages), [BannerPatterns](https://ads.vk.ru/doc/api/resource/BannerPatterns), [BannerFields](https://ads.vk.ru/doc/api/resource/BannerFields) и [TargetingsTree](https://ads.vk.ru/doc/api/resource/TargetingsTree). Не фиксируйте package_id из чужого примера.
5. Проверяйте родительские статусы, лимит, дату начала/окончания и timezone, расписание и причины модерации. Отсутствие показов может быть связано с каждым из них, а не только со ставкой.
6. Разделяйте модель оплаты, стратегию ставок, целевое действие и целевую стоимость. Сумма лимитов групп не равна прогнозу расхода. Нельзя трактовать оптимизацию на лид как оплату за каждый лид.
7. После модерации активная реклама может начать показы согласно расписанию; пополнение баланса может возобновить активные кампании. Создание формы отдельно от создания кампании не включает расход автоматически.

## План изменения

Для каждого объекта запишите: текущие значения, целевые значения, причина, зависимые сущности, разрешение, проверка после записи, путь восстановления. Полезный результат аудита: таблица «уровень → дефект → доказательство → действие → критерий результата».

Рекомендуйте изменения бюджета только после анализа данных и явного запроса на управление. Проверять ставки и анализировать их можно без изменения кабинета. Отсутствующие бизнес-цели, суммы, даты и владельцев оставляйте незаполненными, а не выводите из технических дефолтов.
