# Контракт работы с API

DOC, 2026-09-09: [устройство API](https://ads.vk.ru/doc/api/info/Устройство%20API), [авторизация](https://ads.vk.ru/doc/api/info/Авторизация%20в%20API), [доступ](https://ads.vk.ru/help/features/help_api).

## Авторизация и контекст

- API использует OAuth2 Bearer; не подставляйте токен старого `api.vk.com/method/ads.*`. В документации встречаются хосты ads.vk.com и ads.vk.ru: выбирайте текущий документированный хост, не пересылайте заголовок Authorization автоматически через произвольный редирект.
- Client Credentials — собственный аккаунт. Agency Client Credentials — клиент агентства/менеджера. Authorization Code — сторонний аккаунт при доступности такого flow. Токен агентства сам по себе не является токеном клиента.
- Проверяйте возвращённые scopes. Для чтения выбирайте необходимые разрешения; не запрашивайте права на платежи и запись ради аудита. OAuth code проверяйте вместе со state и зарегистрированным redirect URI.
- Документация ограничивает связку clientId–user пятью токенами. Используйте срок `expires_in`, не создавайте токен на каждый запрос. Обновление меняет access token: синхронизируйте refresh между процессами. Не удаляйте все токены как автоматическое лечение ошибки 403.
- Секреты передаются через защищённое окружение/хранилище, никогда через Markdown, git, аргументы, логи или URL исследования. Доступ через браузер не требует извлечения cookies.

## HTTP и версии

Ресурсы VK Ads используют одновременно v1/v2/v3. У рекламных планов и групп чаще v2, у лид-форм — документированные v1, у подписок — v3. Не заменяйте версию поиском по строке. Некоторые изменения выполняются POST, не PATCH; метод определяется страницей ресурса.

Перед запросом сверяйте тип, required, writable/readable, choices, лимиты и семантику вложений. Примеры могут быть старыми или неполными: не копируйте их целиком как рабочий payload. В частности, учебный quick start с `status=active` не безопасный шаблон черновика.

`fields` сокращает ответ, но должен включать поля для проверки целостности. Коллекции обычно возвращают `count, offset, limit, items`; дефолт 20, максимум 50 по общему контракту, исключения проверяются по методу. Постранично обходите до пустого ответа/полного набора, дедуплицируйте ID; не объявляйте первую страницу всем кабинетом. Фильтры и sorting поддерживаются не всеми полями; вложенные поля нельзя фильтровать по общему правилу.

Дата по умолчанию Europe/Moscow, если метод не указывает иначе. Денежные значения и метрики иногда приходят строками: для денежных расчётов используйте decimal; сохраняйте исходную единицу измерения.

## Ошибки и повторы

- 400: разберите `error.fields`, исправьте конкретное поле; не повторяйте без изменений.
- 401: проверьте контекст и срок токена; один согласованный refresh, затем повтор чтения.
- 403: права/тип кабинета/лимит токенов — не основание менять роли автоматически.
- 404: проверьте объект, аккаунт, архив и версию пути.
- 429: учитывайте текущие `X-RateLimit-*` и Retry-After, если есть; при необходимости читайте `/api/v2/throttling.json`. Числовой универсальный RPS не установлен.
- 5xx/timeout: ограниченные повторы чтения с backoff. Для записи сначала перечитайте состояние и найдите результат операции. При неопределённости остановите повтор, не создавайте дубликат.

Перед разрешённой записью сохраните только необходимые исходные поля приватно, сформируйте diff, проверьте влияние на связанные сущности. После записи выполните GET и сравните. Успех HTTP не подтверждает модерацию, показы или поступление лидов.
