# Лид-формы и интеграции

DOC: [LeadForms](https://ads.vk.ru/doc/api/resource/LeadForms), [LeadForm](https://ads.vk.ru/doc/api/resource/LeadForm), [Leads](https://ads.vk.ru/doc/api/resource/Leads), [Subscriptions](https://ads.vk.ru/doc/api/resource/Subscriptions), [Subscription](https://ads.vk.ru/doc/api/object/Subscription).

- Список и создание: `/api/v1/lead_ads/lead_forms.json`. Чтение и обновление: `/api/v1/lead_ads/lead_forms/<lead_form_id>.json`. Обновление выполняется POST. Созданная форма получает активный статус, но это не запуск рекламной кампании.
- В update секции `contact_fields`, `result_info`, `agreement`, `notifications`, `pages` **полностью заменяются**. Для изменения описания результата сначала прочитайте весь result_info, измените поле и передайте сохранённые остальные значения. Не затирайте сайт, телефон или код частичным вложенным объектом.
- Перед редактированием проверяйте ad_plan_ids, ad_group_ids, banner_ids; для активных кампаний документирован флаг `get_active_form_ad_plans=1`. Архивирование/возврат используют специальные ресурсы; нельзя просто считать произвольное изменение status эквивалентом.
- `/api/v1/lead_ads/leads.json` поддерживает фильтры по форме/плану/группе/объявлению и диапазону created_at. Данные персональные: запрашивайте минимальное, храните приватно; отчёт о качестве может обходиться агрегатами.
- Email и VK Messenger в редакторе — уведомления о новых лидах, не полноценная двусторонняя CRM-интеграция. VK Messenger зависит от типа кабинета и связанного VK ID. Не добавляйте получателей без запроса.
- Подписки `/api/v3/subscription.json` работают отдельно от старых v2/subscriptions. По текущему объекту Subscription для лидов есть resource `LEAD`; callback_url обязан быть HTTPS. Старые примеры ошибки перечисляют другие значения — сверяйте объект, не копируйте список ошибки как контракт.
- При webhook-интеграции сначала проверьте существующие подписки и владельца; создавайте только при разрешении. Рекомендуется дедупликация событий, журнал доставки без контактов, повторная сверка через чтение лидов и раздельная обработка тестовых заявок. Не приписывайте VK неподтверждённую схему подписи webhook.
- Входящие статусы качества из CRM не равны исходящей доставке лидов. [Качество лидов](https://ads.vk.ru/help/general/lead_forms/lead_transfer) описывает отдельную воронку CRM/коллтрекинга. Токены и webhook URL храните как секреты, а не в файлах навыка.

Тестовый лид может попасть реальным получателям и в CRM. «Проверить форму» без разрешения тестовой отправки означает офлайн-валидацию и предпросмотр. После согласованного теста проверяйте факт доставки и идентификатор, а не только уведомление об успехе в браузере.
